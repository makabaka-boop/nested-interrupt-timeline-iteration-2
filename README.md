# 中断控制器回放页（TypeScript，无真实硬件）

一个纯模拟的中断控制器：可配置 **1～8 条中断线**，每条有唯一 ID、优先级、
边沿/电平模式、处理程序所需 tick 与可选的**临界执行区间（写共享寄存器的不可
抢占窗口）**；事件可在指定 tick 触发（raise）、撤销电平（lower）、屏蔽
（mask）、解除屏蔽（unmask）或在阶段 A 调整优先级/模式。回放输出至多
**500 tick** 的执行栈、进入/抢占/恢复证据、门槛阻挡证据与待处理位证据，页面
时间轴、逐 tick 表格与日志**引用同一条轨迹、同一个有效门槛**。

## Tick 内固定顺序（状态机）

每个 tick 严格按以下顺序推进：

1. **阶段 A 应用事件**：同一 tick 的多个事件按 JSON 列表顺序生效。
2. **阶段 B 处理上一 tick 的完成**：栈顶处理程序在上一 tick 执行完最后一个
   tick 后，于本 tick 出栈（因此「完成」与「执行最后一拍」分属相邻两个 tick）。
3. **阶段 C 调度/抢占**：
   - 先从**执行栈中所有尚未结束的临界区间**取最高优先级门槛（无生效区间则无附加门槛）；
   - 栈空：取优先级最高的可运行待处理线进入；
   - 栈非空：待处理线只有优先级**同时严格高于当前栈顶与该门槛**才能抢占；
   - **同优先级**永不抢占，按待处理时刻 `since`、再按 ID 排队等待；
   - 未获准者**保留原待处理位与排序证据**（`since`/`hits` 不变），裁决记录其被挡原因
     （`critical-gate` / `below-top` / `queue`）。
4. **阶段 D 执行**：栈顶处理程序执行 1 tick；被抢占而挂起的帧此 tick
   **不执行、不消耗 handlerTicks**。

## 临界执行区间（criticalSections）

设备处理程序写共享寄存器的几拍内，控制器挡住不足够高优先级的中断，但真正紧急
的中断仍可进入。每条线可在自身 `handlerTicks` 内配置**互不重叠**（允许相邻）
的整数区间：

```jsonc
{ "id": "A", "priority": 2, "mode": "edge", "handlerTicks": 5,
  "criticalSections": [ { "startTick": 2, "endTick": 4, "priorityFloor": 5 } ] }
```

- 区间按该处理程序**已经实际执行的拍数**计数（1 起算、含端点）：处理程序被抢占
  而挂起的拍不前进，区间随之**冻结**，帧恢复后从同一拍**继续**，完成时正确退出。
- 阶段 C 对栈中**每一帧**用 `startTick ≤ elapsed+1 ≤ endTick` 判定区间是否生效，
  再取所有生效区间 `priorityFloor` 的**最大值**作为当前有效门槛（嵌套时内层更严
  门槛也会挡住外层窗口内的普通中断）。
- 抢占条件是 `pri(候选) > pri(栈顶)` **且** `pri(候选) > priorityFloor`（均为严格）；
  因此区间内低于/等于门槛的中断等待并保留待处理位，严格高于门槛者当拍即可进入。
- 阶段 A 的 **setPriority 当拍参与裁决**；电平线完成重入时区间计数随**新帧**重置。
- 未配置 `criticalSections` 的旧场景轨迹**完全不变**（门槛恒为 `null`，无 block 日志）。
- 有效门槛、来源帧、生效区间与每条阻挡线及原因同时写入每拍 `arbitration`，
  状态卡、时间轴（🔒/⛔）、逐拍表格与日志共用这一份证据。

## 语义要点

- **边沿线**：屏蔽期间触发保留 **1 个待处理位**，屏蔽期内重复触发**合并**
  （轨迹中 `hits` 为合并次数，`since` 保留最早时刻）；处理程序运行期间再次
  触发也只挂 1 位，完成后重入一次，不会无限重入。
- **电平线**：输入保持有效即反复可调度；处理完成的那个 tick 若电平仍有效，
  立即重新成为待处理位（下一 tick 可再次进入）。`lower` 撤销未消费的电平
  待处理位；`mask` 挂起调度但不撤销输入电平，`unmask` 时若电平仍有效则
  重新可调度（解除屏蔽本身不会合成边沿）。
- **屏蔽正在运行的线**不会杀掉其当前处理程序，只影响后续调度资格。
- **setPriority** 在阶段 A 立即生效：抢占判断使用双方**当前**优先级，
  因此调低运行中线的优先级后，严格更高的等待线**当 tick** 即可抢占；
  调度日志打印的优先级与决策所用的是同一组。
- **setMode** 真正切换模式时，旧模式遗留的触发状态全部失效：丢弃该线
  的待处理位；切到边沿时同时忘掉已记电平（不合成边沿，与 unmask 同理）。
  运行中的处理程序不受模式切换影响，继续完成。

## 目录

```
src/model.ts          类型定义与排序规则（含 CriticalSection / 裁决证据）
src/simulator.ts      核心状态机：ReplayController（step/advance）+ runReplay
src/scenarios.ts      预置演示（含临界区间、嵌套门槛）
src/main.ts           回放页（时间轴 / 逐 tick 表格 / 日志三视图同源联动）
src/tests/reference-machine.ts  独立重写的逐 tick 参考状态机
src/tests/gate-machine.ts       第三套表驱动逐拍状态机（临界门槛专用）
src/tests/run-tests.ts          手写期望 + 批量等价 + 200 随机场景模糊测试
src/tests/critical-sections.test.ts  Vitest：门槛机逐拍核对嵌套/合并/重入/屏蔽/边界
```

## 使用

```bash
npm install
npm test            # 手写断言 + 参考状态机交叉核对 + 200 随机模糊场景
npm run test:vitest # Vitest：独立逐拍门槛机核对临界区间各场景
npm run build       # 类型检查并打包到 dist/main.js
npm run serve       # 启动 http://localhost:8000 查看回放页
```

页面左侧编辑中断线与事件 JSON 后「载入并重放」，可用 单步 / +5 / 整批 三种
方式推进；点击时间轴格子、表格行或日志行可联动定位同一 tick。

## 测试如何核对

- **手写期望序列**：嵌套抢占、同优先级按 `since`+ID 等待、边沿屏蔽保留/
  重复合并、电平重入、电平屏蔽/解除、严格高优先级门槛、运行期边沿重入、
  模式切换丢弃旧待处理位、运行中调级当 tick 可抢占；以及临界区间的门槛阻挡、
  紧急中断进入、区间边界（单拍/端点/全程）、嵌套取全栈最高门槛、电平重入
  计数重置、屏蔽与门槛互斥、阶段 A 调级当拍越门槛、阻挡原因三分类。
- **逐 tick 参考状态机**：`reference-machine.ts` 独立实现同一套语义，永远
  一次只推进 1 tick；被测实现分别以批次 1 / 2 / 3 / 5 / 11 / 一次性推进，
  逐 tick 比较完整快照（栈、待处理位、电平、屏蔽、动作、剩余 tick、
  **以及仲裁门槛与每个被挡候选的原因**）。
- **Vitest 门槛状态机**：`gate-machine.ts` 以第三种表驱动写法逐拍重放，
  在批次 1 / 3 / 整批下与产品实现逐拍对齐，覆盖嵌套抢占、边沿合并、
  电平重入、屏蔽与临界区间边界。
- **模糊测试**：固定随机种子生成 200 个随机配置/事件场景（约 40% 的线
  带随机互不重叠临界区间），同样与参考机对齐，覆盖不同批次推进结果一致。
- **500 tick 上限**：持续有效的电平线无限重入，恰在 500 tick 截断并置
  `truncated` 证据。
- **旧轨迹不变**：全部未配置 `criticalSections` 的历史场景断言保持原样，
  门槛字段恒为 `null`、无 block 日志。
