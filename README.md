# 中断控制器回放页（TypeScript，无真实硬件）

一个纯模拟的中断控制器：可配置 **1～8 条中断线**，每条有唯一 ID、优先级、
边沿/电平模式与处理程序所需 tick；事件可在指定 tick 触发（raise）、撤销电平
（lower）、屏蔽（mask）或解除屏蔽（unmask）。每条线还可配置 **临界执行区间**
（criticalSections）：设备处理程序写入共享寄存器的几拍内，不足够高优先级的
中断不得抢占，真正紧急的中断仍可进入。回放输出至多 **500 tick** 的
执行栈、进入/抢占/恢复证据、待处理位证据与每拍有效门槛，页面时间轴、
逐 tick 表格与日志**引用同一条轨迹**。

## Tick 内固定顺序（状态机）

每个 tick 严格按以下顺序推进：

1. **阶段 A 应用事件**：同一 tick 的多个事件按 JSON 列表顺序生效。
2. **阶段 B 处理上一 tick 的完成**：栈顶处理程序在上一 tick 执行完最后一个
   tick 后，于本 tick 出栈（因此「完成」与「执行最后一拍」分属相邻两个 tick）。
3. **阶段 C 调度/抢占**：
   - 先取**有效门槛**：执行栈上所有帧（含被抢占挂起的帧）中，已执行拍数
     落在 `[from, to)` 内的临界区间的**最高 threshold**（无则视为无门槛）；
   - 栈空：取优先级最高的可运行待处理线进入；
   - 栈非空：仅**严格高于栈顶优先级、且严格高于有效门槛**的待处理线可抢占；
   - **同优先级**永不抢占，优先级等于门槛也不算严格更高；未获准者保留
     原待处理位与排序证据（since / hits），按 `since`、再按 ID 排队等待。
4. **阶段 D 执行**：栈顶处理程序执行 1 tick；被抢占而挂起的帧此 tick
   **不执行、不消耗 handlerTicks**。

## 语义要点

- **边沿线**：屏蔽期间触发保留 **1 个待处理位**，屏蔽期内重复触发**合并**
  （轨迹中 `hits` 为合并次数，`since` 保留最早时刻）；处理程序运行期间再次
  触发也只挂 1 位，完成后重入一次，不会无限重入。
- **电平线**：输入保持有效即反复可调度；处理完成的那个 tick 若电平仍有效，
  立即重新成为待处理位（下一 tick 可再次进入）。`lower` 撤销未消费的电平
  待处理位；`mask` 挂起调度但不撤销输入电平，`unmask` 时若电平仍有效则
  重新可调度（解除屏蔽本身不会合成边沿）。
- **屏蔽正在运行的线**不会杀掉其当前处理程序，只影响后续调度资格。
- **setPriority** 在阶段 A 立即生效：抢占判断使用双方**当前**优先级，
  因此调低运行中线的优先级后，严格更高的等待线**当 tick** 即可抢占；
  调度日志打印的优先级与决策所用的是同一组。
- **setMode** 真正切换模式时，旧模式遗留的触发状态全部失效：丢弃该线
  的待处理位；切到边沿时同时忘掉已记电平（不合成边沿，与 unmask 同理）。
  运行中的处理程序不受模式切换影响，继续完成。
- **临界区间**：每条线可在自身 `handlerTicks` 内配置若干**互不重叠**的区间
  `{ from, to, threshold }`（整数门槛）。区间按该处理程序**已经实际执行的
  拍数**计数（`from <= elapsed < to` 时生效），被抢占**挂起期间不前进**；
  帧恢复后继续计数，帧完成（出栈）即退出。有效门槛取栈上**所有**未结束
  区间的最高值——包括被抢占挂起的帧（跨帧门槛）；阶段 A 的优先级修改与
  门槛在**同一拍**参与裁决。每个 tick 的 `effectiveThreshold`、
  `thresholdSources` 与 `blocked`（被挡线及其当前优先级、栈顶优先级、
  门槛）写入轨迹，时间轴门槛行、逐 tick 表格与 `block` 日志展示同一数值。
  **未配置临界区间的线行为与旧版完全一致**（门槛恒为 null、无阻挡记录）。

## 目录

```
src/model.ts          类型定义与排序规则（含 CriticalSection / BlockedInfo）
src/simulator.ts      核心状态机：ReplayController（step/advance）+ runReplay
src/scenarios.ts      预置演示（含临界区间示例）
src/main.ts           回放页（时间轴 / 逐 tick 表格 / 日志三视图同源联动）
src/tests/reference-machine.ts      独立重写的逐 tick 参考状态机
src/tests/helpers.ts                测试共享小工具
src/tests/simulator.test.ts         手写期望（旧场景，含「无门槛」不变式）
src/tests/critical-sections.test.ts 临界区间手写期望（边界/嵌套/电平/屏蔽/调级）
src/tests/crosscheck.test.ts        批次等价 + 200 随机场景模糊测试
```

## 使用

```bash
npm install
npm test          # Vitest：61 个断言（含参考状态机交叉核对）
npm run build     # 类型检查并打包到 dist/main.js
npm run serve     # 启动 http://localhost:8000 查看回放页
```

页面左侧编辑中断线与事件 JSON 后「载入并重放」，可用 单步 / +5 / 整批 三种
方式推进；点击时间轴格子、表格行或日志行可联动定位同一 tick。

## 测试如何核对

- **手写期望序列**：嵌套抢占、同优先级按 `since`+ID 等待、边沿屏蔽保留/
  重复合并、电平重入、电平屏蔽/解除、严格高优先级门槛、运行期边沿重入、
  模式切换丢弃旧待处理位、运行中调级当 tick 可抢占。
- **临界区间边界**：`from` 前不生效、`to` 当拍退出、`from=0` 首拍后生效、
  多区间间隙无门槛、等于门槛不算严格更高、挂起帧区间不前进且跨帧参与
  最高门槛、被挡线当拍调级当拍放行、电平/边沿合并/屏蔽与门槛的交互。
- **旧场景不变式**：所有未配置临界区间的场景（含全部旧演示）逐 tick 断言
  `effectiveThreshold === null`、`thresholdSources` 与 `blocked` 为空。
- **逐 tick 参考状态机**：`reference-machine.ts` 独立实现同一套语义，永远
  一次只推进 1 tick；被测实现分别以批次 1 / 2 / 3 / 5 / 11 / 一次性推进，
  逐 tick 比较完整快照（栈、待处理位、电平、屏蔽、动作、剩余 tick、
  有效门槛、门槛来源、被挡线）。
- **模糊测试**：固定随机种子生成 200 个随机配置/事件场景（约 40% 的线带
  随机临界区间），同样与参考机对齐，覆盖不同批次推进结果一致。
- **500 tick 上限**：持续有效的电平线无限重入，恰在 500 tick 截断并置
  `truncated` 证据。
